# Linux PCVR (WiVRN) Implementation Plan

## Goal
Ship Nightfall as a VR gamestream client on Linux PCVR (x86_64) via WiVRN/Monado, reusing the same Godot project with platform conditionals.

## Current State
- CMake `linux` preset exists; debug x86_64 .so builds (129MB)
- Release x86_64 .so **missing**
- `godotopenxrvendors` has Linux .so binaries (debug + release, x86_64 + arm64)
- Godot 4.7 Beta 2 export templates include Linux (debug + release, x86_64 + arm64)
- `nightfall-stream.gdextension` has Linux entries for debug/release x86_64 + arm64
- Zero platform conditionals in GDScript
- No Linux export preset in `export_presets.cfg`

## Decisions
- x86_64 desktop first (arm64/SteamOS later)
- AI-3D (depth estimation) **stubbed on Linux** — disable, add C++ TFLite later
- Passthrough: runtime check of supported blend modes; cycle Off/Starfield only if ALPHA_BLEND unsupported
- Controller models: **skip on Linux** — use Godot's default XR controller mesh
- HEVC decode: **VAAPI only** — no software fallback
- Same Godot project, `OS.get_name()` platform checks (`"Android"` vs `"Linux"`)
- `openxr/extensions/meta/passthrough=true` in project.godot left as-is — unsupported extensions ignored by compliant runtimes

## Phase 1: Build Infrastructure

### 1a. Build release x86_64 .so
```bash
cd addons/nightfall-stream
VCPKG_ROOT=/var/home/tyrone/Development/Personal/vcpkg VCPKG_DEFAULT_TRIPLET=x64-linux \
  cmake --preset=linux -DCMAKE_BUILD_TYPE=Release -B build/linux-release
cmake --build build/linux-release
```
Output: `bin/linux/libnightfall-stream.linux.template_release.x86_64.so`

### 1b. Add `NightfallLinux` export preset to `export_presets.cfg`
Add `[preset.2]` with:
- `name="NightfallLinux"`
- `platform="Linux Desktop"`
- `runnable=true`
- `export_path="./Nightfall-Linux-x86_64"`
- `architectures/x86_64=true`, `arm64=false`
- `custom_template/debug=""` (uses installed Godot templates)
- `custom_template/release=""`
- `xr_features/xr_mode=1` (OpenXR)
- No Meta/Pico/Android XR vendor extensions
- No gradle/keystore/Android permissions
- `script_export_mode=2`
- `texture_format/bptc=true`, `texture_format/s3tc=true` (desktop compression)

### 1c. Update `build.sh` with `--linux` flag
- `--linux` sets `PRESET="NightfallLinux"`, `OUTPUT="Nightfall-Linux-x86_64"`
- Skips all Android steps: unzip, Java, TFLite, AAR, gradle
- Runs `--export-debug` (or `--export-release` with `--release`) via Godot headless
- Cleans `openxr_action_map.tres` after export
- No `--install` support on Linux (no adb)

## Phase 2: Platform Conditionals in GDScript

All guarded by `OS.get_name()` checks.

### 2a. SSL cert paths (`main.gd:902-903`)
```gdscript
if OS.get_name() == "Android":
    OS.set_environment("CURL_CA_BUNDLE", "/system/etc/security/cacerts/")
    OS.set_environment("SSL_CERT_FILE", "/system/etc/security/cacerts/")
else:
    OS.set_environment("CURL_CA_BUNDLE", "/etc/ssl/certs/ca-certificates.crt")
    OS.set_environment("SSL_CERT_FILE", "/etc/ssl/certs/")
```

### 2b. Controller model loading (`main.gd:1255-1290`)
```gdscript
if OS.get_name() == "Android":
    _load_controller_models()
# else: skip, use Godot default XR controller mesh
```

### 2c. Passthrough / environment blend mode
**`settings_controller.gd` `toggle_passthrough()`:**
- Before setting blend mode, check `interface.get_supported_environment_blend_modes()`
- If `ALPHA_BLEND` not in supported modes → remove passthrough mode 0 from cycle
- On Linux without passthrough camera: cycle Off(1)/Starfield(2) only

**`main.gd` startup passthrough restore:**
- Default `passthrough_mode = 1` (Off/OPAQUE) on Linux if `ALPHA_BLEND` unsupported
- Check before setting initial blend mode

### 2d. Depth estimator / AI-3D
**`main.gd`:**
```gdscript
if OS.get_name() == "Android":
    depth_estimator = DepthEstimatorModule.new(self)
    depth_estimator.setup()
```

**`depth_estimator.gd`:**
- Add `var _platform: String` set in `_init()` from `OS.get_name()`
- `setup()`: if Linux, skip SubViewport creation, log "Depth estimation disabled on Linux"
- `process()`: early return if Linux

**`settings_controller.gd`:**
```gdscript
func cycle_ai_3d_mode():
    if OS.get_name() == "Linux":
        return  # AI-3D not available on Linux
    if main.sbs_mode > 0:
        return
    ...
```
- Grey out AI-3D button on Linux (similar to SBS greying out AI-3D)

### 2e. Passthrough labels per platform
```gdscript
if OS.get_name() == "Linux":
    passthrough_labels = ["Off", "Starfield"]  # No real passthrough
else:
    passthrough_labels = ["On", "Off", "Starfield"]
```
Adjust mode indices accordingly.

## Phase 3: Input via WiVRN
- Godot's built-in OpenXR plugin handles `XR_EXT_hand_tracking` and standard controller profiles
- OpenXR action map auto-generated by Godot; should work through WiVRN
- Test: trigger grip, thumbstick, A/B/X/Y, menu button
- If specific controller profiles missing, add to `openxr_action_map.tres`
- **No code changes expected** — WiVRN translates Quest controller input to standard OpenXR actions

## Phase 4: Audio
- Stream audio plays on PC by default (FFmpeg → PulseAudio/PipeWire)
- WiVRN captures desktop audio via PipeWire and forwards to Quest
- **No code changes expected**

## Phase 6: Testing Matrix
| Test | Expected |
|------|----------|
| WiVRN connection | Quest shows Nightfall |
| OpenXR init | Standard OpenXR through Monado |
| Composition layers | Cylinder layers render (WiVRN supports) |
| Controller input | Standard OpenXR actions work |
| Passthrough | ALPHA_BLEND if HMD supports, else Off/Starfield |
| Audio | PipeWire capture via WiVRN |
| mDNS discovery | Works via Avahi (NIGHTFALL_HAS_AVAHI) |
| Stream connect | Moonlight protocol, HEVC via VAAPI |
| AI-3D | Greyed out / disabled |
| SBS | Should work (comp layer based, runtime-agnostic) |

## Risks
1. **WiVRN cylinder layer support** — if not fully supported, fallback to projection layer rendering
2. **VAAPI HEVC decode** — untested; FFmpeg VAAPI init may need configuration in C++ layer
3. **WiVRN known issues** — NVIDIA not well optimized, right eye transparency (fixed recent), double vision regression (open)
